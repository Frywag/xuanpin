# 选品全流程共同知识与执行总纲

> 本文是所有执行人员和 AI 大模型接手任务时的统一入口。  
> 目标是让任何一个子任务负责人拿到本文和对应任务书后，可以直接开始设计、开发、测试和交付，不需要重新理解项目背景。

---

## 1. 项目目标

本项目建设的是“女装跨境选品全流程数据与分析系统”，目标平台为 Amazon / TikTok Shop / Shein。

完整链路如下：

```text
插件 HTTP MCP 数据源
+ 前端采集数据源
+ 站外趋势轻量输入
+ 自有/供应链人工输入
→ 统一候选数据包 CandidateDataPacket
→ L1 粗筛
→ L2 精调研
→ L3 多平台比对
→ Priority Score + S/A/B/C 分级
→ 选品推荐 XLSX
→ 交接给铺货底座
```

最终交付不是单次报告，而是一套可以不断扩展的数据源与分析基础设施：

1. 新增一个插件时，按插件 HTTP MCP 数据源规范接入。
2. 新增一个网站时，按前端采集 Adapter 规范接入。
3. 新增一个分析维度时，进入 CandidateDataPacket 和 L1/L2/L3 分层规则。
4. 所有最终推荐必须能追溯到数据源和证据，不允许模型凭空判断。

SellerSprite 卖家精灵插件数据源已经实现，后续工作不得再把 SellerSprite 当成需要从零开发的任务。它在本项目中的定位是“已验证基线”和“其他插件 MCP 化的参考样板”。

### 2.2 当前 P0：扩展未实现数据源

## 7. 插件 HTTP MCP 已完成基线：SellerSprite

SellerSprite 是已完成基线，不是后续待开发任务。后续插件组要开发的是 Helium10、Jungle Scout、Kalodata、FastMoss、EchoTik 等其他插件或工具。SellerSprite 在文档中的作用是提供可复制的工程模式：如何从浏览器登录态得到可复用会话、如何验证会话、如何请求插件 endpoint、如何做脱敏、如何输出可被分析系统消费的结构化数据。

执行员工没有任何原始代码材料时，也必须能理解下面这些已验证逻辑。后续插件开发时，不要求照抄 SellerSprite 的 extension_id 或 endpoint，而是照抄它的工程步骤：

```text
1. 人工在浏览器或插件环境中完成登录。
2. MCP 服务只读取已授权登录态，不要求员工复制 token。
3. 会话层扫描浏览器 profile 或插件本地存储，提取候选凭证。
4. 用一个低风险查询验证凭证是否有效。
5. 凭证有效后才允许工具层调用真实业务 endpoint。
6. 工具层按业务能力封装，而不是一个字段一个工具。
7. 输出 raw artifact、normalized artifact、summary、collection meta。
8. meta 只记录 token_source / credential_source，不记录 token 明文。
9. 所有输出进入 SourceEnvelope，再进入 CandidateDataPacket。
```

|---|---|

| extension_version | `5.0.3` |

### 7.2 已验证登录态读取方式

已验证脚本逻辑：

1. 优先读取环境变量 `SELLERSPRITE_AUTH_TOKEN`。
2. 扫描 `userdata.glob("*/Default")`。
3. 进入每个 profile 的 `Local Extension Settings/<extension_id>`。
4. 读取 `.log` / `.ldb` 文件。
5. 用正则从本地存储中找 `token`。
6. 对候选 token 去重。
7. 用 harmless ASIN 的 quick-view 请求验证 token 是否有效。
8. 成功后只返回 token 所在 source/profile，不输出 token。

可复用源码片段如下。其他插件不复制其中的 SellerSprite 常量，但要复制“环境变量优先、profile 扫描、候选凭证去重、验证成功才返回”的结构。

```python
EXTENSION_ID = "lnbmbgocenenhhhdojdielgnmeflbnfb"
EXTENSION_VERSION = "5.0.3"
TOKEN_SEED = "500003.1364508470"
BASE_URL = "https://e.sellersprite.com"

def candidate_tokens(userdata):
    env_token = os.environ.get("SELLERSPRITE_AUTH_TOKEN")
    if env_token:
        yield ("env", env_token)
    for default in sorted(userdata.glob("*/Default")):
        storage = default / "Local Extension Settings" / EXTENSION_ID
        if not storage.exists():
            continue
        files = [p for p in storage.iterdir() if p.suffix in {".log", ".ldb"}]
        for path in sorted(files, key=lambda p: p.stat().st_mtime, reverse=True):
            text = path.read_bytes().decode("utf-8", "ignore")
            for match in re.finditer(r'\{"avatar".*?"token":"([^"]+)"\}', text):
                yield (str(default), match.group(1))
```

凭证验证源码片段如下：

```python
def find_valid_token(userdata, marketplace, test_asin):
    seen = set()
    for source, token in candidate_tokens(userdata):
        if token in seen:
            continue
        seen.add(token)
        try:
            payload = request_json(
                f"/v2/extension/competitor-lookup/quick-view/{marketplace}",
                token,
                {
                    "asins": test_asin,
                    "source": "BEST_SELLER",
                    "miniMode": "false",
                    "withRelation": "false",
                    "withSaleTrend": "false",
                },
                timeout=20,
            )
        except Exception:
            continue
        if payload.get("code") == "OK":
            return token, source
    raise SystemExit("No valid SellerSprite token found.")
```

关键验证 endpoint：

```text
/v2/extension/competitor-lookup/quick-view/{marketplace}
```

验证参数：

```json
{
  "asins": "<test_asin>",
  "source": "BEST_SELLER",
  "miniMode": "false",
  "withRelation": "false",
  "withSaleTrend": "false"
}
```

返回 `code == "OK"` 才认为 token 有效。

### 7.5 SellerSprite MCP 化时必须保留的成功经验

1. 不要求用户复制 token。
2. 不把 token 写入报告、日志、Markdown、截图说明。
3. 用单 ASIN 验证登录态，再跑批量。
4. 记录 `token_source`，但不记录 token 值。
5. batch size 和 sleep 可配置。
6. endpoint family 要按业务能力封成 MCP tool。
7. 输出 raw artifact、normalized artifact 和 meta，不只返回临时响应。

### 7.6 其他插件开发时的迁移方式

其他插件不能照搬 SellerSprite 的接口路径，但必须复用以下抽象：

| SellerSprite 中的概念 | 其他插件迁移方式 |
|---|---|
| `EXTENSION_ID` | 换成 Helium10 / Jungle Scout / Kalodata / FastMoss / EchoTik 的浏览器扩展 ID 或 Web App source_id |
| `candidate_tokens()` | 改成对应插件的 cookie、localStorage、IndexedDB、extension storage 或 session header 候选读取器 |
| `find_valid_token()` | 改成该插件的低风险验证请求，例如 account profile、quota、single product preview、keyword search preview |
| `request_json()` | 改成统一 HTTP client，自动注入 headers、cookies、random request id、timeout、retry policy |
| `collect_quick_view()` | 改成业务能力工具，例如 keyword research、product database、creator trend、live commerce analytics |
| `collection-meta.json` | 保留同类 meta，必须写 credential_redacted=true |

其他插件任务完成后，交付的不是“我找到了某个接口”，而是可稳定运行的 HTTP MCP 服务、工具清单、字段映射、脱敏日志和回放测试。

### 8.2 统一商品模型细节

### 8.3 Adapter 契约

每个前端采集 Adapter 必须实现：

```python
class ProductSourceAdapter(Protocol):
    name: str
    version: str

    def discover(self, request: DiscoveryRequest) -> AsyncIterator[ProductRef]: ...
    async def fetch_product(self, ref: ProductRef) -> RawProductRecord: ...
    def normalize(self, raw: RawProductRecord) -> NormalizedProduct: ...
    def normalize_offer(self, raw: RawProductRecord) -> OfferSnapshot: ...
    async def healthcheck(self) -> SourceHealth: ...
```

本项目扩展评论/差评时，应在此基础上增加可选能力：

```python
async def fetch_reviews(self, ref: ProductRef, *, rating_max: int = 3, limit: int = 100) -> RawReviewRecord: ...
def normalize_reviews(self, raw: RawReviewRecord) -> list[ReviewRecord]: ...
```

### 8.4 采集 Runner 顺序

遇到 `ACCESS_BLOCKED` 类错误时，任务进入 `ACCESS_BLOCKED`，不得自动规避。

### 8.5 RawStore 细节

RawStore 用内容哈希保存原始数据：

```text
raw://<source>/<market>/<product_id>-<hash>.json
```

作用：

1. 标准化出错时可回放。
2. 页面变化时可比较。
3. 审核时能回看原始证据。
4. 分析推荐可以绑定 artifact。

### 8.6 SnapshotStore 细节

SnapshotStore 至少包含：

1. `products` 主表：按 `(source, market, product_id, sku)` upsert。
2. `offer_snapshots`：价格/库存/评分快照只追加。
3. `variant_snapshots`：颜色尺码级快照只追加。

报价快照不能覆盖历史，后续用于价格、库存和评分变化分析。

### 8.7 CDP 与访问挑战

参考项目通过 CDP 会话管理真实浏览器：

1. 启动浏览器/CDP。
2. 获取 `cdp_url` 和 PID。
3. 整批任务复用同一个会话。
4. 验证市场、地区、币种。
5. 遇验证码、Cloudflare、登录墙、异常流量提示时保存检查点，等待人工处理。

挑战检测信号包括：

```text
captcha
cloudflare
suspicious_traffic
login
access_challenge
```

规则：

1. 不绕过验证码。
2. 不刷新冲撞。
3. 不自动换代理规避。
4. 保存 checkpoint。
5. 等待人工处理后 resume。

## 10. AI 执行规则

任何 AI 大模型接手任务时必须遵守：

1. 不编造数值。
2. 不把 Google Trends 指数当销量。
3. 不输出 token/cookie/Auth-Token/API key。

6. 缺字段必须写入 `missing_fields`。
7. 推荐理由必须绑定 `evidence_refs`。
