# 前端采集系统组任务书

---

## 1. 组目标

建立一个可扩展的前端数据源采集系统，用于采集插件和账号 token 接口拿不到的数据。

前端采集系统要服务选品全流程，而不是做一次性页面爬虫。系统必须支持 L1/L2/L3 分层控制采集成本，同时保留“先全量采集、再统一分析和分级”的架构可能性。当前不能把前端采集顺序写死为一定发生在分级之后，必须保存原始证据，标准化输出，并把结果交给分层分析系统。

P0 先覆盖：

1. TikTok Shop 商品榜、搜索/类目页、商品详情、视频/达人信号。
2. Shein 榜单、New In、商品详情、收藏热度、评分评论、上新节奏。
3. Zara / H&M / Shein 等快时尚标杆站点的上新节奏、商品详情、价格、图片、趋势元素。
4. Amazon 前台未完成页面：榜单、搜索结果、详情页、评论/差评。

P1 再扩展：

1. Pinterest / Instagram / 小红书 / 抖音 / TikTok 内容侧趋势采集。
2. 更多独立站/品牌站/快时尚站点商品、价格、图片、趋势元素。
3. 与插件 MCP 数据源联动的 L3 多平台同款比对。

已验证基线已经证明前端采集不应按“页面字段脚本”理解，而应按完整工程边界理解：授权范围、限流、Adapter 契约、Raw Evidence、Snapshot Store、Challenge Handling、Checkpoint、Offline Replay、Workbook Export、Tests。执行人员不需要访问任何原始代码材料；本任务书会直接写出需要复用的模型、契约、流程和源码片段。

### 2.3 核心模型细节

前端采集标准模型至少包含以下概念。

`QualityStatus`：

| 状态 | 含义 |
|---|---|
| `VALID` | 可进入分析 |
| `PARTIAL_SOURCE_MISSING` | 部分来源缺失，可降置信度进入分析 |
| `PARSE_FAILED` | 解析失败，不进入分析 |
| `ACCESS_BLOCKED` | 访问受阻，等待人工或换采集方式 |
| `OUT_OF_SCOPE` | 非目标市场、非目标类目或非目标页面 |
| `STALE` | 数据过旧 |
| `QUARANTINED` | 数据冲突或异常，隔离等待复查 |

`Availability`：

```text
in_stock / out_of_stock / preorder / unknown
```

`Provenance` 必须记录：

```json
{
  "source": "amazon_frontend",
  "market": "US",
  "authorization_id": "public_or_authorized_profile_id",
  "adapter_version": "0.1.0",
  "schema_version": "frontend.product.v1",
  "raw_record_uri": "raw://amazon_frontend/US/B0XXXX-hash.json",
  "observed_at": "2026-06-26T00:00:00Z",
  "source_updated_at": null
}
```

`RawProductRecord` 必须包含：

1. `ref`
2. `payload`
3. `content_hash`
4. `fetched_at`
5. `fetch_method`
6. `raw_record_uri`

`NormalizedProduct` 建议字段：

1. `product_id`
2. `parent_product_id`
3. `sku`
4. `canonical_url`
5. `language`
6. `title`
7. `brand`
8. `seller`
9. `category_path`
10. `description`
11. `title_zh`
12. `description_zh`
13. `fabric`
14. `lining`
15. `country`
16. `favorite_count`
17. `first_seen_at`
18. `colors`
19. `sizes`
20. `attributes`
21. `media`
22. `quality_status`

`OfferSnapshot` 建议字段：

1. `currency`
2. `list_price`
3. `sale_price`
4. `discount_percent`
5. `availability`
6. `stock_quantity`
7. `rating`
8. `review_count`
9. `promotion_text`

硬性规则：

1. 金额不得用 float 表达，必须用字符串或 Decimal。
2. 有价格就必须有币种；没有币种的价格视为无效字段。
3. 页面没给出的数值必须是 `null`，不得用 `0` 代替。
4. 解析失败的字段必须进入 `field_issues` 或 `missing_fields`。

from datetime import datetime
from decimal import Decimal
from enum import Enum
from typing import Optional

from pydantic import BaseModel, Field, field_validator, model_validator

SCHEMA_VERSION = "1.0.0"

class QualityStatus(str, Enum):
    VALID = "VALID"
    PARTIAL_SOURCE_MISSING = "PARTIAL_SOURCE_MISSING"
    PARSE_FAILED = "PARSE_FAILED"
    ACCESS_BLOCKED = "ACCESS_BLOCKED"
    OUT_OF_SCOPE = "OUT_OF_SCOPE"
    STALE = "STALE"
    QUARANTINED = "QUARANTINED"

class Availability(str, Enum):
    IN_STOCK = "in_stock"
    OUT_OF_STOCK = "out_of_stock"
    PREORDER = "preorder"
    UNKNOWN = "unknown"

class Provenance(BaseModel):
    source: str
    market: str
    authorization_id: str
    adapter_version: str
    schema_version: str = SCHEMA_VERSION
    raw_record_uri: str
    observed_at: datetime
    source_updated_at: Optional[datetime] = None

class ProductRef(BaseModel):
    source: str
    market: str
    product_id: str

class RawProductRecord(BaseModel):

    fetch_method: str
    raw_record_uri: str = ""

class NormalizedProduct(BaseModel):
    provenance: Provenance
    product_id: str
    parent_product_id: Optional[str] = None
    sku: Optional[str] = None
    canonical_url: Optional[str] = None
    language: Optional[str] = None
    title: str
    brand: Optional[str] = None
    seller: Optional[str] = None
    category_path: list[str] = Field(default_factory=list)
    description: Optional[str] = None
    colors: list[str] = Field(default_factory=list)
    sizes: list[str] = Field(default_factory=list)
    attributes: dict[str, str] = Field(default_factory=dict)
    media: list[dict] = Field(default_factory=list)
    quality_status: QualityStatus = QualityStatus.VALID

class OfferSnapshot(BaseModel):
    provenance: Provenance
    product_id: str
    sku: Optional[str] = None
    currency: Optional[str] = None
    list_price: Optional[Decimal] = None
    sale_price: Optional[Decimal] = None
    discount_percent: Optional[Decimal] = None
    availability: Availability = Availability.UNKNOWN
    stock_quantity: Optional[int] = None
    rating: Optional[Decimal] = None
    review_count: Optional[int] = None
    promotion_text: Optional[str] = None

    @field_validator("list_price", "sale_price", mode="before")
    @classmethod
    def reject_float(cls, v):
        if isinstance(v, float):
            raise ValueError("金额不允许使用 float,请传入 Decimal 或字符串")
        return v

    @model_validator(mode="after")
    def currency_required_with_price(self):
        if self.currency is None and (
            self.list_price is not None or self.sale_price is not None

            raise ValueError("存在价格时必须显式提供币种")
        return self

RawStore 核心：

```python
import hashlib
import json
from pathlib import Path
from typing import Protocol

def content_hash(payload: dict) -> str:
    blob = json.dumps(payload, sort_keys=True, ensure_ascii=False).encode()
    return hashlib.sha256(blob).hexdigest()

class RawStore(Protocol):
    def put(self, source: str, market: str, product_id: str, payload: dict) -> str: ...
    def get(self, uri: str) -> dict: ...

class LocalRawStore:
    def __init__(self, root: Path) -> None:
        self.root = Path(root)
        self.root.mkdir(parents=True, exist_ok=True)

    def put(self, source: str, market: str, product_id: str, payload: dict) -> str:
        h = content_hash(payload)
        rel = Path(source) / market / f"{product_id}-{h[:16]}.json"
        path = self.root / rel
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_text(
            json.dumps(payload, ensure_ascii=False, indent=2),
            encoding="utf-8",
        )
        return f"raw://{rel.as_posix()}"

    def get(self, uri: str) -> dict:
        if not uri.startswith("raw://"):
            raise ValueError(f"非法 URI: {uri}")
        return json.loads(
            (self.root / uri[len("raw://"):]).read_text(encoding="utf-8")
        )
```

Challenge 检测核心：

```python
class ChallengeResult(BaseModel):
    blocked: bool
    kind: str | None = None
    evidence: list[str] = Field(default_factory=list)
    url: str

_SIGNALS = (
    ("captcha", ("<iframe title=\"recaptcha", "hcaptcha", "captcha challenge")),
    ("cloudflare", ("cf-challenge", "checking your browser", "verify you are human")),
    ("suspicious_traffic", ("unusual traffic", "suspicious traffic", "automated requests")),
    ("login", ("sign in to continue", "log in to continue", "login required")),
    ("access_challenge", ("please enable js and disable any ad blocker", "captcha-delivery.com")),
)

def detect_challenge(*, html: str, visible_text: str, url: str) -> ChallengeResult:
    haystack = f"{html}\n{visible_text}".casefold()
    visible = (visible_text or "").casefold()
    if _looks_like_visible_product_page(visible):
        return ChallengeResult(blocked=False, url=url)
    for kind, signals in _SIGNALS:
        matched = [signal for signal in signals if signal in haystack]
        if matched:
            return ChallengeResult(blocked=True, kind=kind, evidence=matched, url=url)
    return ChallengeResult(blocked=False, url=url)
```

Checkpoint 核心：

```python
class RunCheckpoint(BaseModel):
    run_id: str
    profile: str
    profile_version: str
    market: str = "US"
    market_verified: bool = False
    market_signals: list[str] = Field(default_factory=list)
    discovered_urls: list[str] = Field(default_factory=list)
    completed_urls: list[str] = Field(default_factory=list)
    current_url: str | None = None
    current_category_cursor: str | None = None
    current_color: str | None = None
    current_size: str | None = None
    raw_artifact_paths: list[str] = Field(default_factory=list)
    last_successful_operation: str | None = None
    waiting_for_human_reason: str | None = None

class CheckpointStore:
    def __init__(self, path: Path) -> None:
        self.path = Path(path)

    def save(self, checkpoint: RunCheckpoint) -> None:
        self.path.parent.mkdir(parents=True, exist_ok=True)
        temp_path = self.path.with_suffix(self.path.suffix + ".tmp")
        temp_path.write_text(checkpoint.model_dump_json(indent=2), encoding="utf-8")
        temp_path.replace(self.path)

    def load(self, *, expected_profile: str | None = None, expected_profile_version: str | None = None) -> RunCheckpoint:
        checkpoint = RunCheckpoint.model_validate_json(self.path.read_text(encoding="utf-8"))
        if expected_profile and checkpoint.profile != expected_profile:
            raise ValueError(f"站点规则不匹配: {checkpoint.profile} != {expected_profile}")
        if expected_profile_version and checkpoint.profile_version != expected_profile_version:
            raise ValueError("站点规则版本不匹配")
        return checkpoint
```

## 7. Adapter 契约

每个站点至少实现：

```python
class SiteAdapter(Protocol):
    source_id: str
    supported_markets: list[str]
    adapter_version: str

    def discover(self, request: FrontendCollectionRequest) -> list[ProductRef]:
        ...

    def fetch_product(self, ref: ProductRef) -> RawProductRecord:
        ...

    def fetch_reviews(self, ref: ProductRef, limit: int) -> list[RawReviewRecord]:
        ...

    def normalize(self, raw: RawProductRecord) -> NormalizedProduct:
        ...

    def normalize_offer(self, raw: RawProductRecord) -> OfferSnapshot:
        ...

    def healthcheck(self) -> HealthcheckResult:
        ...
```

已验证 Adapter 契约已经跑通 `discover / fetch_product / normalize / normalize_offer / healthcheck`。本项目新增 `fetch_reviews` 用于 L2 差评采集；如果某站点不支持评论采集，必须返回明确的不支持原因，而不是返回空列表冒充成功。

站点 adapter 只做站点相关逻辑：

1. 发现 URL。
2. 获取页面原始证据。
3. 解析页面结构。
4. 映射为统一字段。
5. 标记缺字段和质量状态。

站点 adapter 不做：

1. 分层分析。
2. PScore 计算。
3. XLSX 推荐报告。
4. 跨站点合并。
5. 绕过验证码或登录挑战。

## 8. Runner 执行流程

按已验证 Runner 编排逻辑，P0 runner 必须按以下顺序执行：

```text
1. 读取 FrontendCollectionRequest
2. AuthzProvider.check：确认站点、市场、字段、频率是否允许
3. PlatformRateLimiter.try_acquire：按 source_id + market 限流
4. adapter.healthcheck：检查站点可用性
5. adapter.discover：发现候选商品 URL 或 product_id
6. 对每个 ProductRef：
   6.1 fetch_product 获取原始证据
   6.2 RawStore 保存 raw artifact 和 content_hash
   6.3 normalize / normalize_offer 标准化
   6.4 quality check 标记字段问题和质量状态
   6.5 SnapshotStore upsert product
   6.6 SnapshotStore append offer_snapshot
   6.7 如 layer=L2 且需要评论，fetch_reviews 并保存 review artifacts
   6.8 detect_changes 记录价格、标题、评论数等变化
   6.9 checkpoint 保存进度
7. 导出 FrontendSourceEnvelope
8. 导出人工验收 workbook
```

失败处理：

1. 401/403：标记 `ACCESS_BLOCKED`，不重试。
2. 429：按限流策略退避，超过阈值暂停。
3. Captcha / Cloudflare / 登录墙：保存 checkpoint，退出 `WAITING_FOR_HUMAN`。
4. 单商品解析失败：标记 `PARSE_FAILED`，继续下一个商品。
5. 市场不匹配：标记 `OUT_OF_SCOPE`，不得混入 US 市场样本。

## 10. 存储与回放

RawStore 必须遵守以下已验证逻辑：

1. 原始记录用内容哈希去重。
2. 原始证据 URI 使用 `raw://<source>/<market>/<product_id>-<hash>.json`。
3. 原始证据和标准化数据分开保存，便于 replay。
4. 原始证据不得覆盖旧版本。

SnapshotStore 必须遵守以下已验证逻辑：

1. `products` 表按 `(source, market, product_id, sku)` upsert。
2. `offer_snapshots` 只追加，不覆盖。
3. `variant_snapshots` 只追加，不覆盖。
4. 价格、库存、评分、评论数都按快照记录，方便观察变化。

Offline Replay 必须支持：

```bash
python -m src.frontend_sources.cli.collect_sites --replay data/raw/frontend_sources/amazon_frontend/run_20260626_001
```

回放测试的目标不是重新访问网站，而是用已保存的 raw artifact 验证 parser、normalizer、字段映射和导出逻辑。

## 12. 目标站点 P0 要求

### 12.1 站点优先级

本轮前端采集不是只做 Amazon。SellerSprite 已经覆盖了 Amazon 插件数据，当前更大的缺口在 TikTok Shop、Shein、快时尚标杆站点和 Amazon 未完成前台页面。

| source_id | 站点 | P0 页面 | 核心价值 |
|---|---|---|---|
| `tiktok_shop_frontend` | TikTok Shop | 商品榜、搜索/类目、商品详情、视频/达人入口、评论/互动 | 趋势赛道、内容带货、达人关联 |
| `shein_frontend` | Shein | 品类榜、Trends、New In、热销、商品详情、收藏、评分评论 | Shein 数据稀缺，收藏和上新节奏是爆款信号 |
| `zara_frontend` | Zara | New In、品类页、商品详情、价格、图片、颜色尺码 | 快时尚上新方向和版型颜色参考 |
| `hm_frontend` | H&M | New Arrivals、品类页、商品详情、价格、颜色尺码 | 快时尚价格带和基础款节奏 |
| `amazon_frontend` | Amazon | 榜单、搜索、详情、评论/差评中未完成部分 | 补足插件拿不到的详情、评论和前台证据 |

P0 最低要求：至少选一个未实现站点跑通完整链路。优先建议 Shein 或 TikTok Shop，因为它们是业务文档中明确的数据缺口。

### 12.2 榜单/搜索/类目发现

目标页面：

1. TikTok Shop 商品榜、搜索结果、类目页。
2. Shein 品类榜、Trends、New In、热销榜。
3. Zara / H&M New In、品类页、搜索结果。
4. Amazon Best Sellers / New Releases / Movers & Shakers / 搜索结果页中未完成部分。

输出：

```json
{
  "ref_type": "product_url",
  "source_id": "shein_frontend",
  "market": "US",
  "canonical_url": "https://example.com/product/123",
  "product_id": "site_product_123",
  "rank_context": {
    "page_type": "new_in",
    "category_path": ["Women", "Dresses"],
    "rank": 12
  },
  "evidence_refs": []
}
```

### 12.3 商品详情页

P0 字段：

| 字段 | 要求 |
|---|---|
| `product_id` | 必填，站点内商品 ID；Amazon 为 ASIN |
| `canonical_url` | 必填 |
| `title` | 必填 |
| `brand` | 可缺失但要记录 |
| `seller` / `shop_name` | 可缺失但要记录 |
| `category_path` | 尽量获取 |
| `main_image` / `media` | 至少主图 |
| `sale_price` / `list_price` | 有币种才有效 |
| `rating` | 可缺失 |
| `review_count` | 可缺失 |
| `favorite_count` / `heart_count` | Shein 重点字段，拿不到记录 missing |
| `video_count` / `creator_count` | TikTok Shop 重点字段，拿不到记录 missing |
| `bsr` | Amazon 可选字段，拿不到记录 missing |
| `colors` / `sizes` | P0 尽量获取，L2 补全 |
| `availability` | 必填枚举，未知为 `unknown` |
| `first_seen_at` / `new_in_signal` | 上新节奏字段，快时尚和 Shein 重点 |

### 12.4 评论/差评/互动

评论采集的触发顺序待定。默认成本控制方案是 L2 后只对入围商品采集评论；如果业务确认需要先全量采集再统一分析，则 C1 必须采用采集预算、页数上限和 evidence 分层标记，避免无限翻页和无证据数据进入分析。

P0 评论或互动字段：

1. `review_id`
2. `rating`
3. `title`
4. `body`
5. `date`
6. `variant`
7. `verified_purchase` / `buyer_badge`
8. `helpful_count` / `like_count`
9. `language`
10. `raw_record_uri`
11. `video_id` / `creator_id`，TikTok Shop 可选

低分评论或负向互动优先级：

1. 1 星和 2 星。
2. 最近评论。
3. 与质量、尺码、面料、色差、透明度、起球、做工、退货有关的评论。

评论/互动采集不能无限翻页。P0 默认每个入围商品最多 50 条低分评论或 50 条关键互动；如果访问受限，记录原因并让 L2 分析降低置信度。

## 13. L1/L2/L3 采集策略

本节是默认成本控制方案，不是最终架构定论。前端采集到底是先按 L1/L2/L3 触发，还是先对目标站点做一轮受控全量采集后再统一分析和分级，需要在第 1 天由主线程、C1、D1 共同确认。

| 层 | 采集策略 | 禁止事项 |
|---|---|---|
| L1 | 榜单/搜索发现、基础详情、基础量价、评分评论数 | 不采全量评论，不做多平台深比 |
| L2 | 只对入围款采详情补全、评论/差评、Q&A | 不对淘汰款采高成本数据 |
| L3 | 只对终选款采跨平台同款候选、更多图片、属性、价格带 | 不扩大到全量候选 |

无论采用哪种顺序，采集请求都必须带 `collection_mode` 和 `layer_hint`。adapter 和 runner 必须能根据策略控制采集深度，并在 SourceEnvelope 中记录本次数据服务的层级或全量采集批次。

## 17. 验收标准

P0 前端采集通过标准：

1. Amazon 至少一个榜单或搜索页可发现商品。
2. 至少 10 个商品详情有完整原始证据包。
3. 至少 3 个入围商品能采到评论/差评，或明确记录拿不到的原因。
4. 每个商品都有 `FrontendSourceEnvelope`。
5. 每个关键字段都有 `EvidenceRef` 或进入 `missing_fields`。
6. 标准化输出能被分层分析系统消费。
7. 遇访问挑战时保存 checkpoint，不绕过。
8. 离线回放能复现至少一个商品解析。
9. 工作簿能打开，并能人工核查字段问题。
10. 测试至少覆盖 adapter contract、raw store、replay、workbook export。

阻断项：

1. 无 raw evidence 的商品进入分析。
2. 把缺失数值写成 0。
3. 价格无币种。
4. 绕过验证码或登录挑战。
5. US 市场样本混入其他市场。
6. 无法 replay。
