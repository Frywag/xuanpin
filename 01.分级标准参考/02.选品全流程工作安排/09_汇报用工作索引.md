# 选品全流程工作汇报索引

> 本文件用于你把握全局、向团队或外部人员说明工作安排。它不替代执行任务书；执行细节以 `00_共同知识与执行总纲_完整版.md` 和各组任务书为准。

---

## 1. 项目一句话

建设一套女装跨境选品数据与分析系统，把插件账号态数据、前端网页数据、站外趋势数据和供应链输入统一成候选品数据包，再通过 L1/L2/L3 分层分析输出选品推荐 XLSX，最后交接给铺货底座。

---

## 2. 当前最重要的判断

项目最大工作量集中在三块：

| 主线 | 工作量 | 原因 |
|---|---|---|
| 插件 HTTP MCP 数据源 | 极重 | 登录态服务化、多人 HTTP 调用、工具接口、真实字段、限流、脱敏、测试 |
| 前端采集系统 | 极重 | CDP/HTTP、站点适配、原始证据、访问挑战、评论/差评、离线回放 |
| 分层分析系统 | 重 | L1/L2/L3 成本控制、证据绑定、评分、推荐理由、XLSX |

字段标准、报告模板、QA checklist、趋势词计划不单独占人，由主线程临时调用 GPT-5.5 生成草案。

---

## 3. 推荐人员

固定 4 人：

| 人 | 方向 | 关键产出 |
|---|---|---|
| B1 | 其他插件 MCP 会话授权与 HTTP 服务 | Helium10/Jungle Scout/Kalodata/FastMoss/EchoTik 可多人访问的 HTTP MCP 服务 |
| B2 | 其他插件 MCP 工具接口、字段采集、测试回放与验收 | 非 SellerSprite 插件工具、normalizer、脱敏、多客户端、回放测试 |
| C1 | 前端采集系统与未实现站点适配 | Adapter、RawStore、Snapshot、CDP、Checkpoint、站点字段、评论/互动证据 |
| D1 | 分层分析、评分与报告输出 | CandidateDataPacket、Gate、成本控制、证据模型、PScore、XLSX |

---

## 4. P0 里程碑

| 周期 | 目标 | 验收物 |
|---|---|---|
| 第 1 天 | 范围和接口冻结 | 确定一个非 SellerSprite 插件、一个前端站点、CandidateDataPacket v0、前端采集顺序决策 |
| 第 2-3 天 | 新数据源真实跑通 | 插件 HTTP MCP 可启动，至少 1 个工具返回真实字段，前端保存 raw evidence |
| 第 4-5 天 | 数据进入分析 | SourceEnvelope、FrontendSourceEnvelope、CandidateDataPacket、L1/L2 Gate 样例 |
| 第 6 天 | 端到端样例 | 数据源 → CandidateDataPacket → L1/L2/L3 → XLSX |
| 第 7 天 | 验收和汇报 | 脱敏检查、回放样例、P0 验收记录、下周扩展清单 |

---

## 5. P0 通过标准

1. SellerSprite 作为已完成基线，不再重复安排开发。
2. 至少一个其他插件 HTTP MCP 服务可启动。
3. 两个客户端可通过 HTTP 调用新插件服务，不接触 token/cookie。
4. 至少 2 个非 SellerSprite 工具返回真实业务字段。
5. 一个未实现前端网站至少保存 10 个商品详情原始证据包。
6. 至少 3 个入围商品有评论/差评/互动数据，或明确记录拿不到原因。
7. CandidateDataPacket 可由新插件数据和新前端数据生成。
8. L1/L2/L3 按 Gate 执行；若第 1 天决定先全量前端采集，必须有采集预算、页数上限和字段范围。
9. XLSX 推荐表能展示推荐理由、风险、证据和下一步。

执行人员只需要拿到本目录内的 Markdown 文档，不需要访问任何外部源文件。所有已实现参考逻辑、关键流程、源码片段和接口约束都已经写入任务书。

## 7. 主线程每日检查

每天只检查四个问题：

1. 今天哪个数据源真实跑通？
2. 今天哪个字段稳定返回？
3. 今天哪个分析层可以消费真实数据？
4. 今天哪个结果能进入 XLSX 给业务判断？

如果一个工作不能回答这四个问题之一，就不是当前阶段的核心工作。
