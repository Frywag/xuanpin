# GPT 轻量任务池：标准、报告、验收

---

## 1. 定位

这些任务重要，但不应该占固定员工。原因是：

1. 可以由 GPT-5.5 基于真实样例快速生成初版。
2. 不是当前最大阻塞。
3. 后续会随着数据源和分析系统变化而反复调整。

主线程按需把这些任务丢给 GPT 完成即可。

---

## 3. 统一输入材料

所有轻量任务都不能凭空设计，必须吃真实样例或已确定 schema。

主线程给 GPT 轻量任务时，至少提供以下一种材料：

| 材料 | 来源 | 用途 |
|---|---|---|
| `SourceEnvelope` | 插件 MCP 或前端采集 | 生成字段标准、数据源卡、覆盖率检查 |
| `CandidateDataPacket` | 分层分析 D1 | 生成字段字典、缺字段规则、QA checklist |
| `AnalysisResult` | 分层分析 D1 | 生成 XLSX 模板、推荐总表、汇报材料 |
| `EvidenceRef` 样例 | 插件 MCP / 前端采集 / 分析系统 | 检查证据绑定、阻断无证据结论 |
| 真实 workbook | 前端采集或最终报告 | 改进列名、筛选、条件格式 |

轻量任务禁止直接读取 token、cookie、浏览器本地登录态文件。需要解释数据源能力时，只允许使用脱敏后的接口说明和输出样例。

## 4. 字段标准任务提示词

```markdown
你是字段标准助手。请基于以下真实样例数据，生成选品候选数据包字段标准。

输入：

- 插件 MCP SourceEnvelope
- 前端采集 FrontendSourceEnvelope
- CandidateDataPacket schema
- 当前选品目标：女装，Amazon/TikTok Shop/Shein

请输出：

1. candidate_data_packet_schema.md
2. 字段字典
3. 必填/选填/可缺失字段
4. 字段来源
5. 下游用途：L1/L2/L3/PScore/XLSX/152键
6. 缺字段处理规则

约束：

- 不得发明样例中不存在的字段。
- 不确定的字段标为 optional。
- 数值字段必须说明单位和口径。
- 每个关键字段必须说明来源 source_id 和 evidence_refs 绑定方式。
```

## 5. 数据源卡任务提示词

```markdown
你是数据源卡助手。请根据某个数据源的真实输出和接入说明，生成数据源卡。

请输出：

1. 数据源名称和 source_id
2. source_type：plugin / frontend / trend / owned / compliance
3. 采集方式
4. 工具或页面清单
5. 可得字段表
6. 字段下游用途
7. 限制、费用、账号、频率、风险
8. 最小验收标准
9. SourceEnvelope 输出样例
10. EvidenceRef 绑定方式

约束：

- 不得写“可获取所有字段”这类空话。
- 必须区分已验证字段和推测可获取字段。
- 凭证/token/cookie 一律不得出现。
- 必须写明该数据源服务 L1/L2/L3 哪一层。
```

## 6. XLSX 模板任务提示词

```markdown
你是选品 XLSX 报告设计助手。请基于分析输出 schema 设计业务可读的 Excel 工作簿。

输入：

- AnalysisResult schema
- CandidateDataPacket schema
- EvidenceRef 样例
- 3-10 条真实或脱敏 AnalysisResult

请输出：

1. Sheet 清单
2. 每个 Sheet 的列名、字段来源、是否必填
3. 推荐总表列顺序
4. 默认筛选和排序
5. 条件格式规则
6. 缺字段和风险展示规则
7. 3 行样例数据

约束：

- 报告给业务负责人看，不是技术 JSON dump。
- 推荐理由、风险、证据、下一步必须在推荐总表里可见。
- 缺字段不得隐藏。
- XLSX 只从 AnalysisResult 生成，不直接读取插件响应或页面原始 HTML。
```

## 7. QA checklist 任务提示词

```markdown
你是 QA 验收助手。请根据某条主线的交付物生成验收 checklist。

主线类型：

- 插件 HTTP MCP
- 前端采集系统
- 分层分析系统

请输出：

1. 必须通过项
2. 条件通过项
3. 阻断项
4. 测试数据要求
5. 安全检查
6. 复现方式
7. 验收报告模板

约束：

- 明文 token/cookie/Auth-Token 一律阻断。
- 无证据推荐理由一律阻断。
- 编造数值一律阻断。
- 只跑通一次不算稳定通过。
- 无 EvidenceRef 的推荐理由一律阻断。
- 无 raw evidence 的前端商品记录一律阻断。
```

## 9. 项目状态汇总提示词

```markdown
你是项目状态汇总助手。请根据各组进展，输出主线程可读的项目状态。

请输出：

1. 今日结论：是否按计划推进
2. 三条重主线状态：
   - 插件 HTTP MCP
   - 前端采集系统
   - 分层分析系统
3. 已跑通的数据源
4. 已稳定返回的字段
5. 当前阻塞项
6. 明天最重要的 5 件事

约束：

- 不写泛泛而谈。
- 每个状态必须对应具体文件、接口、数据源或测试结果。
- 把“文档完成”和“真实跑通”分开写。
- 必须按插件 HTTP MCP、前端采集系统、分层分析系统三条重主线汇总。
```

## 10. 主线程使用建议

主线程不要把轻量任务做成固定岗位。推荐做法：

1. 重系统负责人产出真实样例。
2. 主线程把真实样例丢给 GPT 生成标准/报告/验收草案。
3. 主线程审核是否符合业务判断。
4. 草案再反向喂给重系统负责人作为接口要求。

这样能避免轻量任务占用人力，又能让文档和标准跟着真实系统走。
