# 三赛道独立 S/A/B 分级：目标业务规则

> 文档性质：目标业务规则，不是当前实现说明
> 业务基线：开发部大项目 7.13 XMind + 本轮用户确认
> 核心结论：三条赛道共享事实和证据，但不共享准入方式、评分公式、等级阈值或深挖名额。

## 1. 已确认的业务规则

1. 三条赛道必须分别运行一遍 S/A/B 分级，各自产出自己的 S、A、B；
2. 三条赛道的分类方式不相通，不能用一个“首个命中”的分类器代替三次评估；
3. 趋势新品必须符合“新推出的款型”；
4. 趋势新品不设置销量、评论数、GMV、收藏数等数据准入门槛；
5. TikTok 等社媒信号、多平台出现类似款可以提高趋势权重，但不是趋势新品的必备门槛；
6. 爆款改款大致需要同时具备：适量销量/需求、评分偏低、负面评论聚类较多；
7. 独立站是趋势发现源，不能因缺少平台销量字段被自动淘汰；
8. 最终分级仍需确定性、可解释、可追溯和可重算。

## 2. 推荐的三个正式赛道名称

| 业务名称 | 建议系统键 | 主要机会 | 默认开发建议 |
|---|---|---|---|
| 趋势新品 | `trend_new` | 新款型正在多个渠道出现或在内容端扩散 | 新品开发或快速跟进 |
| 爆款改款 | `hit_improvement` | 已有需求，但用户痛点明显且可被产品解决 | 改款、替代款或优化版 |
| 长尾直接选品 | `long_tail_direct` | 需求稳定、竞争可切入、无需依赖爆发或明显改款 | 直接选品或轻度差异化 |

说明：赛道描述“为什么值得看”，开发方式描述“公司怎么做”。系统应保留 `track_id` 与 `recommended_development_mode` 两个字段，最终开发方式由人审确认。

## 3. 三赛道不能再采用的旧结构

不应继续使用：

```text
候选 → 按优先级命中一个赛道 → 一次评分 → 一个等级
```

目标结构是：

```text
同一事实候选
  ├─ 趋势新品准入 → 趋势评分 → 趋势 S/A/B
  ├─ 爆款改款准入 → 改款评分 → 改款 S/A/B
  └─ 长尾直接选品准入 → 长尾评分 → 长尾 S/A/B
```

建议允许同一候选进入多条赛道。例如，一个刚推出的款型可以同时有明显尺码差评，它可以获得“趋势 A”和“改款 B”。跨赛道最终只能选一种开发方式时，应在三条评分之后处理，而不是评分之前强制唯一归类。

## 4. 统一对象模型

### 4.1 ProductObservation：单站商品观察

每个具体商品页面形成一条观察，至少包括：

- 平台、站点、URL、商品 ID；
- 标题、图片、类目、价格、品牌；
- 上架/首次发现/新品标签等新鲜度证据；
- 销量、销售额、评论、评分、收藏、内容等来源可提供的信号；
- 版型、颜色、材质、图案、长度、场景等款型属性；
- 字段证据、采集时间、质量状态和缺失原因。

必须区分两个概念：

- **商品/SKU 新鲜度**：该页面、SKU 或系列是否近期上架；
- **市场款型新颖度**：其核心廓形、结构、材质组合或设计元素，相对目标市场历史款型是否新。

页面新品标签只能直接证明前者。趋势新品准入需要两者都有证据，或由业务人员明确确认“这是新推出款型”。

### 4.2 OpportunityCluster：同款式/同趋势机会簇

趋势新品不应只以单个 SKU 为对象。多个站点出现不同商品，但共享同一种新廓形、材质、图案或场景时，应形成一个机会簇。

机会簇应保留：

- 代表款型描述；
- 成员商品和平台；
- 关系类型：同商品、同款式、同趋势；
- 图片、标题、属性和时间证据；
- 首次发现时间和近期新增成员；
- TikTok/社媒关联内容；
- 关系置信度及人工复核状态。

机会簇还必须保存：

- 稳定的 `cluster_id` 与 `cluster_version`；
- 本次运行的成员快照；
- 成员加入、移出和合并/拆分原因；
- 每个 `candidate_id → cluster_id` 的关系证据；
- 与上一版本的 lineage，避免簇变化后历史结果无法解释。

### 4.3 TrackEvaluation：候选 × 赛道结果

正式唯一键为：

```text
(run_id, subject_type, subject_id, track_id)
```

其中 `subject_type` 为 `candidate` 或 `cluster`。每个原始候选在每次运行中必须生成三条候选级评估记录，分别对应三条赛道，即使结果为 `PENDING_DATA` 或 `REJECTED`；趋势机会簇还可以额外生成簇级评估。候选级趋势记录通过 `cluster_id/cluster_version` 引用簇级证据和分数，跨赛道汇总始终以候选级记录为主，避免簇级与商品级结果互相覆盖。

每条结果应包含：

- 准入状态和准入理由；
- 本赛道评分明细；
- S/A/B；
- 置信度；
- 证据引用；
- 缺失字段和补采任务；
- 风险与人工问题；
- 建议开发方式。

## 5. 统一的准入、待补和分级语义

### 5.1 先做赛道准入

| 状态 | 含义 | 是否进入 S/A/B |
|---|---|---|
| `ELIGIBLE` | 已满足本赛道最低事实条件 | 是 |
| `PENDING_DATA` | 方向可能成立，但缺本赛道必备证据 | 否，进入补采池 |
| `REJECTED` | 已被证据否定或命中红线 | 否 |

### 5.2 S/A/B 的统一层级语义

三条赛道可以共享等级的管理含义，但不能共享得分公式：

- **S**：本赛道第一优先级，证据链足以进入人工立项评审；
- **A**：值得定向补数、供应链验证或方案评审；
- **B**：观察、低成本跟踪或等待更多证据；
- **未准入**：不与 B 混淆，必须记录是待补还是已否定。

兼容旧系统时可以附加 `legacy_grade=C`，但内部语义必须保持：`PENDING_DATA` 和 `REJECTED` 的正式 `grade` 均为空。推荐表只展示三个赛道各自已准入的 S/A/B；待补与拒绝分别进入独立审计页。

## 6. 来源角色，而不是来源等级

| 来源角色 | 典型来源 | 主要贡献 | 不应承担的任务 |
|---|---|---|---|
| 款型发现源 | 独立站、品牌站、时尚零售站、New Arrivals | 新款型、设计元素、上新节奏、价格定位 | 不要求提供平台成交量 |
| 内容趋势源 | TikTok、达人内容、社媒 | 内容采用、传播速度、场景和元素共振 | 不单独证明真实成交或长期需求 |
| 交易验证源 | Amazon、TikTok Shop、SHEIN、第三方工具 | 销量、销售额、排名、价格、竞争 | 不独占趋势发现资格 |
| VOC 源 | 评论、退货、客服、内容反馈 | 痛点、严重度、频次、变体差异 | 不能用单条意见直接决定改款 |
| 供应可行性源 | 供应商、自有能力档案 | 成本、MOQ、交期、工艺和质量 | 不能用估算冒充已确认事实 |
| 经营回流源 | 自有订单、利润、退货、内容、库存 | 校准等级与实际经营结果 | 不应与外部市场快照混为一谈 |

来源角色是多值集合 `source_roles[]`，不是单枚举。例如 SHEIN 同时可以是交易验证源与 VOC 源，TikTok Shop 可以是交易验证源与内容趋势源；每条角色判断都应记录依据。TikTok 内容与 TikTok Shop 商品交易应保留为不同来源实体，必要时再建立关联。

## 7. 赛道一：趋势新品

### 7.1 业务目的

尽早发现“刚被推出、正在形成或跨渠道重复出现”的新款型。趋势新品的核心不是当前销量有多大，而是款型是否新、是否正在扩散、是否值得抢时间开发。

### 7.2 准入对象

优先以 `OpportunityCluster` 作为评分对象，也允许只有一个商品观察的早期候选进入 B 级观察。

### 7.3 必备准入条件

“新推出款型”由两组证据联合成立。

**A. 近期推出证据，至少一种：**

- 页面明确标记 `New / New Arrival / Just In / New Collection`；
- 来源提供可信的首次上架/首次可售时间；
- 系统连续监测中，此前快照明确不存在、随后在 `first_seen_at` 首次出现；
- 最新系列、当季发布或新品集合中的明确位置；
- 最早评论、最早内容发布时间和页面上新位置共同支持“近期推出”；
- 业务人员确认该商品或系列为近期推出。

**B. 款型新颖度证据，至少一种：**

- 与目标市场历史款型库对照后，核心款型组合在规定回看窗口内未出现或明显稀少；
- 多站点时序显示该款型元素从无到有、近期开始新增；
- 业务人员基于版型、结构、材质组合和市场历史确认属于新款型；
- 其他经业务批准、可追溯的款型新颖度证据。

单次首次采集只能证明系统此前没有记录，不能证明商品刚上架；页面/SKU 新也不能自动证明市场款型新。

缺近期推出证据或缺款型新颖度证据时统一进入 `PENDING_DATA`；已有证据确认是旧商品或旧款型时才进入 `REJECTED`。不能仅因标题带“new”、系统第一次采到或销量增长就认定为趋势新品。

### 7.4 明确不设置的数据准入门槛

趋势新品准入不要求：

- 最低销量；
- 最低销售额；
- 最低评论数；
- 最低收藏数；
- 最低达人数量；
- 最低增长率；
- 必须进入畅销榜。

这些字段有值时可以作为排序证据，但缺失或数值低不能自动淘汰新款型。

### 7.5 可以提高权重的信号

- 两个或以上不同平台/站点出现相似款型；
- 相似款在近期持续新增，而不是一次性静态重复；
- TikTok/社媒出现同元素内容，且发布时间与上新窗口一致；
- 多个独立创作者自然采用，而非单一广告账户集中投放；
- SHEIN、独立站、品牌站或内容端同时出现相同廓形/元素；
- 设计元素可被清楚描述并转化为产品定义；
- 与公司供应能力、目标人群和价格带有初步匹配。

多平台相似是**加权项而非准入项**。单站真正早期的新品可以进入 B，但不能因为没有第二个平台就直接 C。

### 7.6 建议评分维度

固定权重需通过业务金标校准，P0 先明确维度优先级：

1. **新鲜度与上新可信度**：最高优先级；
2. **跨平台款型共振**：相似款站点数、平台类型和时间密度；
3. **TikTok/内容扩散**：内容数量、创作者广度、近期加速度；
4. **款型可定义性**：廓形、材质、颜色、图案、结构和场景能否明确描述；
5. **目标市场适配**：客群、季节、价格带和渠道适配；
6. **风险**：品牌/IP、极短窗口、明显抄款、数据异常和供应难度。

销量只能作为弱到中等的确认项，不能成为趋势新品的主导分。

### 7.7 S/A/B 建议语义

- **S**：新款型证据明确；出现跨平台/跨来源共振或强 TikTok 扩散；机会定义清楚；关键风险可控，可进入快速立项评审；
- **A**：新款型明确；已有一种强增强信号或多个中等信号；仍需补图片相似、社媒或供应验证；
- **B**：新款型基本成立但当前为单源早期信号，或相似关系置信度较低；进入持续观察；
- **PENDING_DATA**：缺近期推出证据或款型新颖度证据，等待补采；
- **REJECTED**：已确认是旧商品/旧款型、只因销量增长被误判，或命中经业务批准的确定性拒绝红线。

### 7.8 趋势赛道专属补采

- 上架时间、首次发现时间和新品标签；
- 同款式/同趋势的跨平台召回；
- 图片、属性和元素相似证据；
- TikTok 内容发布时间、创作者广度和趋势曲线；
- 新增相似款的时间序列；
- 季节窗口、IP 和供应可实现性。

## 8. 赛道二：爆款改款

### 8.1 业务目的

寻找“已有足够需求证明、用户不满意且问题可以被产品设计解决”的商品。这里的“爆款”不要求是全类目头部，但必须有适量销量或等价的真实需求基础，否则低评分只代表小样本噪音。

### 8.2 三项联合准入条件

爆款改款原则上必须同时满足：

1. **适量销量/需求**：有真实成交、持续销售、足够订单/评论积累或其他可靠交易证据；
2. **评分偏低**：相对同平台、同类目、同时间窗口的评分基准偏低；
3. **负面评论聚类较多**：存在多个重复出现、可归因、可执行的负面问题簇。

不能用以下单项直接准入：

- 只有低评分，没有销量基础；
- 有销量但评分正常；
- 有少量差评但无法形成重复聚类；
- 问题集中在物流、客服、误购等产品无法解决的原因；
- 评分低但样本过少。

### 8.3 “销量适量”的口径

P0 不应硬编码一个跨平台绝对销量阈值。应按以下顺序确定：

1. 同平台 × 同类目 × 同观察窗口的相对分布；
2. 交易型指标优先于收藏、播放等热度指标；
3. 不同平台使用各自可验证的字段，不做未经确认的换算；
4. 由历史优秀、失败和边界商品金标校准“适量”分档；
5. 在配置中版本化，业务审批后生效。

其目的不是找销量最高的商品，而是确保痛点已经影响到足够多的真实用户。

### 8.4 低评分与负面聚类口径

低评分优先使用相对口径：

- 低于同平台同类目评分分位；
- 或低于业务确认的绝对警戒线；
- 同时检查评论量，避免小样本误判。

“聚类较多”至少要同时看：

- 聚类数量；
- 每个聚类的提及频次和占比；
- 严重度；
- 是否跨时间、变体或平台重复；
- 是否可通过版型、尺码、面料、做工、色差、包装或说明解决；
- 原始评论证据是否完整。

具体阈值必须由业务金标校准，后续 Agent 不得自行猜测。

### 8.5 建议评分维度

1. **需求已验证程度**：销量、销售持续性和证据可靠度；
2. **痛点强度**：低评分幅度、聚类数量、频次和严重度；
3. **可改性**：问题是否能被材料、版型、工艺、包装或说明解决；
4. **改后差异化**：改良是否形成清楚卖点，而不是简单修补；
5. **竞争与价格空间**：改后是否仍有价格带和竞争机会；
6. **风险**：品牌/IP、退货原因不可控、供应复杂度和问题不可复现。

### 8.6 S/A/B 建议语义

- **S**：需求基础充分；评分显著偏低；多个高频、可复现、可改的负面聚类；改良方案清楚且风险可控；
- **A**：三项准入成立，但聚类深度、供应实现或差异化仍需验证；
- **B**：需求和痛点方向成立，但样本、严重度或可改性证据较弱，适合补评论/退货/变体数据；
- **未准入**：缺需求基础、评分不低、无重复痛点、痛点不可由产品解决或命中红线。

### 8.7 改款赛道专属补采

- 评论全文而非只有评分；
- 退货原因、客服问题和变体信息；
- 聚类频次、占比、严重度和时间变化；
- 同类竞品是否也存在同一痛点；
- 改良方案、样品验证和目标成本；
- 侵权、结构专利和品牌风险。

## 9. 赛道三：长尾直接选品

### 9.1 业务目的

寻找不依赖短期爆发、也不依赖明显改款的稳定机会：需求持续、竞争分散、价格带合理、供应可承接，可以直接选品或做轻度差异化。

它不等同于“标题中出现 basic/tee/sock 等基础词”，也不等同于所有未命中前两条赛道的剩余商品。

### 9.2 建议准入条件

- 有稳定需求证据或多周期持续出现；
- 不是只靠单次异常增长；
- 竞争结构和评论护城河存在可切入空间；
- 价格带与目标市场基本匹配；
- 商品质量没有必须先改款的明显问题；
- 没有不可接受的品牌/IP、合规或供应风险。

### 9.3 建议评分维度

1. 需求稳定性和持续性；
2. 竞争可突破程度；
3. 价格带与利润结构代理；
4. 供应链能力匹配；
5. 商品事实完整度和直接承接难度；
6. 季节、品牌、质量和库存风险。

### 9.4 S/A/B 建议语义

- **S**：稳定需求、多源或多周期验证、竞争可切入、直接承接路径清楚；
- **A**：市场机会明确，但需补供应、成本或第二来源；
- **B**：具有长尾观察价值，但需求稳定性、竞争或供应证据不足；
- **未准入**：无稳定需求、竞争不可突破、必须先做重大改款或风险不可控。

## 10. 三条赛道的对照

| 项目 | 趋势新品 | 爆款改款 | 长尾直接选品 |
|---|---|---|---|
| 核心问题 | 新款型是否正在形成 | 已有需求的痛点是否值得改 | 稳定机会是否可直接承接 |
| 主要对象 | 机会簇/新款型 | 已有销量商品/产品族 | 稳定商品/细分需求 |
| 销量准入 | 不设门槛 | 必须适量，按平台类目校准 | 需要稳定需求证据 |
| 新鲜度 | 必备 | 非必备 | 非必备 |
| 低评分 | 非必备 | 必备或显著相对偏低 | 通常不应明显偏低 |
| VOC 聚类 | 辅助 | 核心必备 | 风险参考 |
| 多平台相似 | 加权项 | 可用于验证共同痛点和竞争 | 可用于验证容量与价格 |
| 独立站角色 | 核心发现源 | 可提供评论和产品细节 | 可提供稳定细分与定价参照 |
| TikTok 角色 | 内容趋势增强 | 需求与内容验证 | 渠道适配参考 |

## 11. L1/L2/L3 必须按赛道分别执行

### 11.1 趋势新品

- L1：新鲜度和款型事实粗筛，不因无销量降级；
- L2：图片/属性聚类、多平台相似召回、TikTok/社媒补证；
- L3：窗口、已有供应事实、IP 风险和目标平台机会验证；P0 只消费已存在事实并生成补采任务，不负责供应商谈判或给出最终合规结论。

### 11.2 爆款改款

- L1：适量需求 + 低评分 + 评论可用性粗筛；
- L2：评论全文、退货、客服和变体聚类；
- L3：改良方案、竞品共同痛点、已有供应/样品事实验证；P0 不自动发起打样或批准改款。

### 11.3 长尾直接选品

- L1：稳定需求、竞争和价格带粗筛；
- L2：多周期、评论护城河、供应能力和利润结构补证；
- L3：消费已有供应商、成本、MOQ、交期、合规和平台适配事实；缺失时生成定向任务，不在 P0 内谈判、检测或作最终审批。

三条赛道必须有独立的 `max_candidates` 或预算。一个赛道未用完的名额是否可转给另一赛道，属于业务配置，不得默认全局混排。

## 12. 多平台相似关系的边界

| 关系 | 证据要求 | 可用于 |
|---|---|---|
| 同商品 | 商品 ID、GTIN、供应关系或高置信身份匹配 | 量价互验、重复合并 |
| 同款式 | 图片结构、属性、版型和关键细节高度一致 | 竞品与饱和度比较 |
| 同趋势 | 共享廓形、材质、颜色、图案、场景等趋势元素 | 趋势权重和机会簇 |

标题词重叠只能作为召回信号，不能单独确认同商品或同款式。所有低置信度边界关系必须送人工复核。

## 13. 目标交付表结构

建议至少包含：

1. `趋势新品_SAB`；
2. `爆款改款_SAB`；
3. `长尾直接选品_SAB`；
4. `跨赛道汇总`；
5. `待补数据`；
6. `未准入与淘汰依据`；
7. `机会簇与跨平台相似`；
8. `评分明细`；
9. `证据索引`；
10. `数据源覆盖与角色`；
11. `规则版本与运行记录`；
12. `入库152键`（只表示结构，不参与三赛道准入）。

同一候选可以在三张 S/A/B 表中重复出现，完整主键必须使用 `(run_id, subject_type, subject_id, track_id)`；展示层可在同一 run 内简写为 `(candidate_id, track_id)`，但不得用简写覆盖历史或簇级结果。

## 14. 后续 Agent 不得擅自决定的业务参数

以下参数在**启用正式生产准入、评分和等级前**必须由业务金标或业务负责人确认；它们不阻塞数据模型、字段采集、配置槽、回放和测试骨架的实现：

- “新推出款型”的证据有效期和置信度规则；
- 不同来源的新品标签可信度；
- 爆款改款中各平台、各类目的“适量销量”分档；
- 低评分的相对/绝对边界；
- “负面聚类较多”的数量、频次、占比和严重度口径；
- 三条赛道 S/A/B 阈值；
- 三条赛道各自的 L2/L3 名额；
- 第三赛道最终对外名称是“长尾”“直接选品”还是“长尾直接选品”。
- 款型历史库的范围、回看窗口和“市场款型新”的判定口径；
- `same_style/same_trend` 的召回阈值、确认阈值、置信度与簇更新规则；
- 哪些风险属于确定性 `REJECTED`，哪些只能进入人工复核。
- 长尾直接选品的稳定需求观察周期、竞争可切入边界、价格匹配口径和“可直接承接”最低事实条件。

Agent 可以提供回放分布和备选参数，但不得把建议值直接当成已批准业务规则。在这些参数和金标未确认前，只能完成结构、采集、版本化、回放和测试骨架；不得把校准中的结果称为正式生产 S/A/B。

## 15. 禁止用这些捷径修复系统

- 只降低全局 B 阈值，让独立站“勉强通过”；
- 把所有独立站商品直接标成趋势新品；
- 继续保留首个命中唯一赛道；
- 让三条赛道共享同一个 L2 前 40、L3 前 10；
- 趋势新品仍要求最低销量或增长率；
- 把多平台相似设为趋势新品硬门槛；
- 只用低评分定义爆款改款；
- 只用评论数量而不做负面聚类；
- 用标题相似冒充同款；
- 用 152 键填充率决定赛道等级；
- 让 LLM 自由改分或自动批准立项。

## 16. 业务验收要点

1. 每个候选在每个 run 中恰好获得三条候选级评估记录；趋势机会簇可额外获得簇级记录；
2. 趋势新品缺销量时不会被自动降级；
3. 趋势结果 100% 带新款型证据；
4. 多平台类似款只增加趋势权重，不是硬准入；
5. 改款结果 100% 带需求、低评分和负面聚类三类证据；
6. 独立站候选 100% 按来源角色参与趋势判断，不再结构性归零；
7. 三条赛道分别输出 S/A/B 和补采队列；
8. 每个分数和准入结论可追溯、可解释、可重算；
9. 重复运行结果一致率 100%；
10. 与业务人工金标一致率达到 XMind 首版目标 ≥85%。
