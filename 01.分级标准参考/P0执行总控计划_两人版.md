## 1. P0 目标

P0 只证明一件事：两人配置下，Codex 能调度插件 MCP、前端/趋势站点 smoke、样例深采、分层分析和 XLSX 推荐表，形成可追溯的选品数据链路。

P0 必须达成：

1. 跑通 `Kalodata + EchoTik` 两个插件源。
2. 完成 19 个零售站点 + 8 个趋势站的 smoke 状态判定。
3. 至少 5 个前端/趋势站点进入样例深采，每站至少 10 条商品详情或趋势明细 raw evidence。
4. 至少生成 3 个 `CandidateDataPacket`。
5. 输出 1 份 P0 XLSX 推荐表。
6. 推荐理由 100% 绑定 `EvidenceRef` 或明确 `missing_fields`。

## 2. 总体执行路径

```text
范围冻结
→ 插件源并行采集
→ 前端/趋势站并行 smoke
→ 样例深采
→ SourceEnvelope / FrontendSourceEnvelope
→ CandidateDataPacket
→ L1 / L2 / L3
→ XLSX 推荐表
→ 运营验收
```

## 5. 数据结构最低标准

### SourceEnvelope

每个插件源至少输出：

```json
{
  "source_id": "kalodata",
  "source_type": "plugin",
  "market": "US",
  "collection_mode": "mixed",
  "layer_hint": "L1",
  "quality_status": "VALID",
  "records": [],
  "errors": [],
  "artifact_paths": {
    "raw": "",
    "normalized": "",
    "log": ""
  }
}
```

### FrontendSourceEnvelope

每个深采站点至少输出：

```json
{
  "source_id": "princess_polly_frontend",
  "source_type": "frontend",
  "market": "US",
  "collection_mode": "mixed",
  "layer_hint": "L1",
  "quality_status": "VALID",
  "records": [],
  "errors": [],
  "artifact_paths": {
    "raw_evidence_manifest": "",
    "screenshots": "",
    "log": ""
  }
}
```

### CandidateDataPacket

P0 至少 3 个：

```json
{
  "candidate_id": "cand_001",
  "market": "US",
  "source_refs": [],
  "basic_facts": {},
  "market_metrics": {},
  "competition_metrics": {},
  "trend_signals": [],
  "product_opportunity": {},
  "evidence_refs": [],
  "missing_fields": []
}
```

7. `P0_验收报告.md`

## 7. 风险红线

1. 不输出账号密码。
2. 不输出 token、cookie、Auth-Token、完整敏感 header。
3. 不绕过验证码、登录墙、Cloudflare、403、429、设备校验或付费墙。
4. 没有 raw evidence 或 EvidenceRef 的字段不能进入推荐理由。
5. 缺字段必须写入 `missing_fields`，不能写成 0。
6. 价格必须带币种。
