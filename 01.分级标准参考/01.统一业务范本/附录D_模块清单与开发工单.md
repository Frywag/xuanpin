# 附录 D · 模块清单与开发工单（IT 拆解直接用）

> 主纲 §6 的开票规格。**每个模块 = 一张工单卡**：边界 / 输入 / 输出 / 依赖表(附录A) / 依赖接口(附录B) / 依赖规则(附录C) / 验收标准 / 优先级 / 责任系统。
> IT 可直接据每张卡拆 Epic→Story。优先级：**P0 地基**先做（M10→M2→M3→M4→M9），P1 规模化，P2 经营闭环。
> 验收标准均为可测的"完成定义(DoD)"。

---

## M10 · 主数据底座（P0｜责任：数据中台）

| 项 | 内容 |
|---|---|
| 边界 | 建主数据物理表 + 唯一写入口 + 变更通知 + 血缘。**只做底座，不含业务逻辑** |
| 输入 | 各来源主数据写入请求 |
| 输出 | 主数据读/订阅服务；变更事件流 |
| 依赖表 | t_legal_entity, t_brand, t_platform, t_shop, t_spu, t_sku, t_canonical_product, t_canonical_attribute, t_category, t_site_offer |
| 依赖接口 | B1 主数据发布、B2 订阅、B3 决策读、B4 ERP 单据同步、B7 回写 |
| 依赖规则 | 治理铁律（附录A·§7） |
| 验收(DoD) | ①全部 P0 表建成；②主数据只能经 B1 写入（直写被拒）；③变更产生 B2 事件且消费端幂等；④ERP 单据单向同步、无双向打架；⑤任一主数据可查 version 与血缘 |
