> **本文件是唯一主纲**。它把"选品→铺货→刊登→内容→维护→风控→复制/退出"的全部业务逻辑收敛为一套内聚、无矛盾、可执行的统一范本。

## 1. 一句话定位与北极星

用 **Agent 集群替代人工**，把"多平台铺货运营"做成**边际成本极低、可无限复制**的吞吐机器。

- **北极星指标**：人工介入率 ↓（每万 Listing 所需人工工时）。
- **终局规模假设**：10 个 Agent 管理人 → Agent 集群 → 20 平台 → 2000 店 → 20 万产品 → 2000 万 Listing。
- **架构命门——变/不变分离**：把"变的"（平台差异、类目差异、店铺差异）全部沉为配置 + 映射引擎；把"不变的"（6 个通用操作 + Canonical 主数据模型）沉为内核。结果：**加 1 平台 3–5 人天，加 1 类目 0.5–2 人天**。

## 3. 三系统边界（最重要的全局约定）

| 系统 | 定位 | 权威拥有 | 明确**不做** |
|---|---|---|---|
| **数据中台** | 主数据 + 决策数据的**唯一权威源**；本体语义层在此 | SPU/SKU/CanonicalProduct/Category/Brand/LegalEntity/店铺画像/评分/成本/利润/规则/映射配置 | 不执行刊登动作；不做 LLM 推理 |
| **ERP** | 进销存**单据**系统（采购/库存实体/订单/履约/对账） | 采购单、库存实物数、订单、履约状态 | **不再作为商品主数据源**；不作文案/选品事实源 |
| **智能平台**<br>(app-platform, com.xspaceagi) | Agent / Workflow / Skill / MCP 的**运行时** + 多 Agent 编排器 | 运行态：Task、Agent 实例、文案版本、执行日志 | 不持有主数据权威；不绕过中台直写主数据 |

**三条铁律（贯穿全范本）**

1. **主数据单向收敛**：主数据写入只走中台权威接口，其他系统只读镜像；ERP 迁移期单向收敛（中台权威，ERP 订阅），禁双向打架。
2. **确定性操作硬隔离 LLM**：改价 / 改库存 / 上下架 / 字段直填等确定性操作走规则引擎与映射引擎，**架构层面禁止经 LLM 决定数值**（财务级铁律）。
3. **SOP 为单一事实来源**：规则与流程定义沉在中台（SOP/规则表），Agent 是执行主体之一，不得内嵌与 SOP 冲突的硬逻辑。

## 4. 五层业务架构

每层职责互斥，跨层只能"上调下、下回上"。

```
L1 战略决策层  主对象=Project：进入/复制/退出、双利润口径、全链路成本血缘
L2 运营计划层  店铺画像(三维分级)、商品画像(S/A/B/C)、铺货计划、活动/广告计划、在线调整规则
L3 执行内核层  ★"不变"沉淀：Canonical Model、6通用Skill、类目属性映射引擎、风险分级发布引擎、执行通道
L4 智能编排层  主干通用运营Agent、专职子Agent(内容/选品/广告/客服)、编排器(★待补)、评审Agent、记忆
L5 数据与知识底座  数据中台(主数据/血缘/评分) + 知识库(平台规则/类目/侵权) + ERP(单据)
```

**6 个通用操作 Skill（不变内核）**：SubmitListing(刊登)、UpdatePrice(改价)、UpdateInventory(改库存)、Delist-Relist(上下架/复活)、SyncStatus(同步状态)、UpdateDetail(改详情)。
**执行通道优先级**：API > 批量上传表 > RPA/紫鸟。

## 5. 端到端业务流（6 个闭环，按价值链顺序）

| # | 闭环 | 层 | 关键步骤（执行者） | 落地附录 |
|---|---|---|---|---|
| 1 | **选品进入** | 选品域→L1 | 三赛道候选 → Priority Score 打分(选品Agent) → 派生商品 S/A/B/C → 机会评分 → 立项 Project → 拨预算 | C·§1, D·M1 |
| 2 | **标准铺货** | L2→L3 | 选品 → 店货匹配 → Canonical 抽取 → 类目映射 → 刊登级别 L1–L4 定档 → 风险分级发布 → 回写 | E, C·§2, D·M2–M4 |
| 3 | **★跨平台复用铺货（样板，D4）** | L3 | 成熟 Listing → 抽 CanonicalProduct → 货选店 → 类目映射 → 换图换文案 → 风险分级发布 → 回写 | E, D·M2/M5 |
| 4 | **在线维护** | L2→L3 | 监控指标 → 命中阈值规则 → 改价/改库存/上下架（**确定性，禁LLM**）→ 执行通道 → 回写校验 | C·§3, D·M6 |
| 5 | **店铺安全风控** | L5→L2 | 平台回传 KPI → 对比红线（按平台配置）→ 安全等级降级 → 限制刊登优先级 → 收缩铺货 → 通知人 | C·§4, D·M7 |
| 6 | **复制/退出决策** | L1 | 周期结算 → 双利润核算 → 命中加码/复制/退出门 → 调预算 → 更新 Project | C·§5, D·M8 |

**铺货样板的最小可发布集**：优先用三平台**共有的 20 个 Canonical 键**（标题/描述/品牌/卖家SKU/产地/附图/库存/售价/材质/面料克重/面料弹性/风格/领型/袖长/门襟/版型/护理/细节/包装尺寸/包装重量）打通发布，再按目标平台补独有项。详见附录 E·§7。

## 7. 核心实体与统一分级口径

**一级业务对象**：Project（决策容器，一级主对象）/ LegalEntity / Platform / Shop / SPU / SKU / Category / CanonicalProduct / Listing / ContentAsset / Brand / Agent·Workflow·Skill·MCP / SOP / Task / Rule。权威源除 Listing（平台为真、中台镜像）、Task/Agent 运行态（智能平台）、库存实物数（ERP）外，**全部在数据中台**。完整属性与关系见附录 A，ER 摘要见 §8。

**统一分级口径（全范本唯一标准，禁再立口径）**

- **商品分级 S/A/B/C**：S 超级潜力 / A 主力 / B 测款 / C 清仓。来源 = 选品 Priority Score 分箱（附录 C·§1），**不另立"高/中/测款/低/清仓"五档**。
- **店铺三维（正交，禁合并）**：① 安全等级 S/A/B/C/D（KPI 红线驱动，可自动降级）；② 刊登优先级 S/A/B；③ 定位标签——拆为**两个子 facet**：货盘定位（通铺/分类/品牌/热销/人群/风格/场景，"卖什么"）+ 内容调性（品牌店/清货店/高毛利店/风格店，"怎么说"）。
- **刊登级别 L1–L4**：内容投入档。**与发布风险等级正交**。
- **发布风险等级**：自动 / 人工。由"操作性质（确定性/创造性）+ 内容质量分级（P0/P1/P2）+ 店铺成熟度门槛"共同决定（附录 C·§2）。
- **备货状态**：现货 / 海外仓 / 无现货。**品质等级**：S/A/B。

## 10. P0 缺口与关键风险

**P0 缺口（不补跑不起来）**

- **主数据无物理表（GAP-09/01/02）**：中台需新建 t_spu / t_canonical_product / t_legal_entity / t_brand / t_category_mapping / t_value_dict（附录 A）。
- **多 Agent 编排器缺失**：外挂 LangGraph 式编排层（模块 M9）。
- **决策值空缺（GAP-03/04）**：55 条 draft 规则 + 7 个成本口径 + Priority Score 权重阈值待业务赋值（附录 C，标 TODO）。

**关键风险**

| 编号 | 风险 | 对策 |
|---|---|---|
| R1 | 中台单点（血缘正确性=业务命脉） | 可观测 + 血缘校验 + 自动决策依赖数据须可追溯 |
| R2 | ERP 迁移期一致性 | 单向收敛（中台权威，ERP 订阅），禁双向 |
| R3 | 侵权残余 | 判据四项：产品本体 + 文字商标 + 外观专利 + 平台 AI 政策（非单看图片） |
| R4 | 过度自动化 | 自动发布带成熟度门槛 + 回滚 + 灰度 |
| R5 | 确定性操作误用 LLM | 架构层硬隔离（财务级铁律） |
