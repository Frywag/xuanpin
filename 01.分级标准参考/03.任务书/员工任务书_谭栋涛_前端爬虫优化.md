你负责 19 个零售站点 + 8 个趋势站的并行 smoke 判定，并从可稳定访问的站点中选择至少 5 个进入样例深采，每站至少 10 条商品详情或趋势明细 raw evidence。

必须完成：

1. 27 个站点 smoke 状态总表。

5. 阻塞站点输出 checkpoint 和失败原因。
6. 前端采集验收报告。

## 4. Smoke 判定模板

每个站点一行：

```text
site_id：

```

`status` 只能使用：

1. `ready_for_deep_collection`
2. `partial_only`
3. `blocked_needs_human`
4. `paid_or_login_required`
5. `not_worth_p0`

## 5. 深采标准

至少 5 个站点进入深采。每个深采站点必须：

1. 至少 10 条商品详情或趋势明细 raw evidence。
2. 保存 raw evidence manifest。
3. 输出 `FrontendSourceEnvelope`。
4. 记录字段覆盖和缺字段。
5. 记录阻塞、失败和重试情况。

建议优先深采：

1. Princess Polly
2. Revolve
3. Lulus
4. Pinterest Trends
5. Google Trends

如这些站点出现阻塞，从 smoke 通过站点中替换。

## 6. FrontendSourceEnvelope 最低格式

```json
{
  "source_id": "princess_polly_frontend",
  "source_type": "frontend",
  "market": "US",
  "collection_mode": "mixed",
  "layer_hint": "L1",
  "quality_status": "VALID",
  "records": [],
  "errors": [],
  "artifact_paths": {
    "raw_evidence_manifest": "",
    "screenshots": "",
    "log": ""
  }
}
```

## 7. 风险红线

1. 不绕过验证码、登录墙、Cloudflare、403、429、设备校验或付费墙。
2. 不保存账号密码、token、cookie、Auth-Token、完整敏感 header。
3. 普通 HTTP 失败但浏览器可访问时，记录为 browser-needed，不要重复高频请求。
4. 拿不到评论、详情、趋势明细时，写明原因，不要伪造字段。
5. 价格没有币种视为无效字段。

## 8. 验收标准

提交前自查：

1. 27 个站点都有 smoke 状态。
2. 至少 5 个站点完成深采。
3. 每个深采站点至少 10 条 raw evidence。
4. 每个深采站点有 `FrontendSourceEnvelope`。
5. 阻塞站点有失败原因和 next_action。
6. 无敏感信息泄漏。
